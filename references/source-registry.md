## 使用优先级

| 问题 | 首选来源 | 说明 |
|---|---|---|
| 单机构当前执行 | 对应机构多维表 | 机构实时协作 |
| 跨机构对比/工作台/查重 | 全量表 | 由机构表汇总，显示最近同步时间 |
| 客户审核结论 | 客户审核表 | 客户侧权威事实 |
| 实际发布/互动 | 客户发布表 + 公开作品页 | 多维表用于汇总，不替代发布登记链路 |
| 当周发布/待审脚本 | 当周执行文档 | 机构每日工作入口 |
| 客户要求/同事承诺 | 群消息 | 由 Deadline 模块增量扫描 |
| 历史缺口修复 | 旧机构电子表格 | 只修明确历史范围，不覆盖当前 Base |

内部问答的当前业务数据必须通过 `query_lifecycle_base` 读取上述 Base。中央同步事实层是历史证据和口径补充，不是达人现状查询的替代数据源。

## 发现规则

1. 机构表不按固定 table_id 清单写死在各 Skill 中；每次列出 Base 表并按稳定表名识别。
2. 全量表名称会带更新时间，必须按固定 table_id 或名称前缀识别。
3. 视图是展示层，不是数据边界；读取不依赖用户当前打开的筛选视图。
4. 新增机构只要建成统一字段且命名为“机构 X 焦尾 执行表”，依赖 Skill 即可发现；正式纳入前仍需字段完整性校验。
